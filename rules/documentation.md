# 文档与文件约定

## 当前状态

- 文档描述**当前有效的**概念、机制、结论和使用方式；历史由 Git 保存。
- 接手者应能从当前文档理解项目，不必追溯旧提交、聊天记录或 Draft。
- 删除文档内容时，同时清理围绕它形成的解释、否定、占位和未来暗示。**删除不是将存在改写为不存在，而是让该概念退出项目的当前描述体系。**
- 文档只保留对当前使用或维护具有独立价值的信息。

## 代码维护

- 新增和修改代码以当前设计为准，不为项目旧版本保留兼容层、适配器或旧行为；当前版本的实际调用方和运行路径仍须正常。
- 日常开发不要求顺带清理无关的遗留实现。只有遗留代码影响当前功能、测试、构建或本次任务时，才需要处理。

## 表述

- 简洁、清晰，不为已经退出当前设计的概念留下说明。
- 区分已验证结论、观察和尚待验证的判断。

## 文件职责

- `README.md`：项目定位与入口。
- `docs/`：研究资料与当前有效的说明。
- `rules/`：参与者（包括 Agent）需要遵守的约定。
- 临时内容遵守 [Draft 隔离](drafts.md)。
