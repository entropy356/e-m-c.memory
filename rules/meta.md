# 规范维护

本文件供人类或 Agent **审查、修改规范时**使用。日常开发按任务读取相关规则文件即可，不必预先加载规范的存在理由。

## 取舍方针

- **实用主义**：以规范对项目开发、理解和维护的实际帮助为准。
- **如无必要，勿增规范**：优先复用、合并或简化现有要求；规则受到质疑时，应能解释保留它的价值。
- **面向 Agent**：执行要求应直接写在对应规则文件中，清楚到无需查阅本文件才能遵守。

## 上下文使用

- **执行规则**：提供相关规则正文及必要的任务上下文。
- **审查或修改规则**：再按需读取本文件的存在意义及相关依据。
- 如果一条规则依赖其存在理由才能正确执行，应补全规则正文。

## 现有规则为什么存在

- [文档：当前状态](documentation.md#当前状态)：让人类与 Agent 了解当前项目时，尽量不必追溯历史。
- [文档：表述](documentation.md#表述)：降低阅读和理解 AI 产出的负担，同时保留必要的不确定性。
- [文档：文件职责](documentation.md#文件职责)：帮助接手者快速定位当前知识与实现。
- [Draft：命名与边界](drafts.md#命名与边界)：让临时材料易于识别，降低误用风险。
- [Draft：隔离](drafts.md#隔离)：允许自由试验和交换材料，同时保持正式内容独立可用。

以上理由可随规则一起调整。
